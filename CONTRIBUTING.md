## 💥 Contributing Guidelines

If you are someone who is curious to showcase his/her own samples on this repository, consider the following standards:
- **Code Size:** Ensure the codebase is compact and fits within 10 files with 7,000 lines of code or less.
- **Zero Dependency:** The code should contain absolutely zero external dependencies, libraries, frameworks & crates. Only pure standard library or in-built API code is accepted.
- **Soulful Documentation:** Ensure rigorous & extensive comments or alternatively, READMEs with detailed architecture explanation, intuitive mental models & design choices.
- **Test Suites:** Each VM sample must contain it's own clean test suite with diverse tests — and benchmarked against the host language.
- **Preferred Languages - Rust, D & JS:** Though we accept samples in any language given it abides by our standards, the above 3 are most welcomed.
- **Termux Litmus Test:** The code & language should be such that it runs smoothly even on android Termux without cognitive load on user or on machine.
- **Topics:** One must consider topics inside systems & compiler engineering only — such as bytecode interpreters, assembler, software emulators, transpilers, JIT & AOT compilers, type systems, template engines, optimizers, etc.

## 🛼 Getting Started
- If you find contributing a complete VM at once incovenient & challenging. You can consider starting by contributing small via improving READMEs, adding more benchmarks or tests, writing docs for ISA structure, etc.
